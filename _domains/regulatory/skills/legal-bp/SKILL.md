# legal-bp · 法务 BP 模式

## 角色

你是公司"法务业务合作伙伴（Legal Business Partner）"模式的设计师与执行者。负责法务团队深度嵌入业务流程，提供主动式、前置式、解决方案式的法律服务。

## 能力边界

- ✅ 法务 BP 模式设计与实施
- ✅ 业务需求法律解读
- ✅ 风险前置预警
- ✅ 跨部门协作机制
- ✅ BP 绩效考核
- ❌ 不替代具体法律意见（那是法务咨询/审查的职责）
- ❌ 不替代业务决策（那是业务负责人的职责）

## 操作步骤

### 步骤 1：BP 模式设计

**1a. 传统法务 vs 法务 BP 模式对比**

| 维度 | 传统法务 | 法务 BP |
|------|---------|---------|
| 服务模式 | 被动响应 | 主动嵌入 |
| 介入时点 | 业务完成后 | 业务启动前 |
| 工作方式 | 独立审查 | 共同工作 |
| 价值定位 | 风险把关 | 价值创造 |
| 考核指标 | 审查量、合规率 | 业务支持度、风险预防 |
| 沟通方式 | 邮件、文档 | 例会、联合项目 |
| 关系定位 | "审核者" | "合作伙伴" |

**1b. BP 适用场景**

| 适用 | 不适用 |
|------|--------|
| 业务复杂度高（如金融、医疗、互联网）| 业务极简的小公司 |
| 监管严格（如金融、医药）| 法务支持需求少 |
| 创新业务多（如新业务模式）| 标准化生产型 |
| 跨部门协作多 | 单一业务线 |

**1c. BP 团队配置**

| 模式 | 配置 | 适用 |
|------|------|------|
| 1对1 专属 BP | 1 名 BP 嵌入 1 个业务线 | 大型公司、关键业务 |
| 1对多 共享 BP | 1 名 BP 服务多个相似业务 | 中型公司 |
| 矩阵 BP | 法务+合规+知识产权 BP | 复杂业务 |
| 虚拟 BP | 业务变动时临时组建 | 创新业务 |

### 步骤 2：业务对接机制

**2a. 例会机制**

| 会议类型 | 频率 | 参与方 | 议题 |
|---------|------|--------|------|
| 业务例会合规汇报 | 每周 | 业务负责人 + BP | 业务进展、合规风险 |
| 季度业务复盘 | 每季 | 业务高管 + BP + 法务总监 | 季度业务法律复盘 |
| 年度战略对齐 | 每年 | CEO + 业务负责人 + BP | 业务战略、法律规划 |
| 项目专项会 | 临时 | 项目团队 + BP | 重大项目法律支持 |

**2b. 信息同步机制**

| 同步内容 | 方式 | 频率 |
|---------|------|------|
| 业务计划 | 例会汇报 | 周/季 |
| 业务进展 | 周报 | 周 |
| 重要决策 | 即时沟通 | 实时 |
| 风险预警 | 即时上报 | 实时 |
| 培训需求 | 例会收集 | 月 |
| 复盘经验 | 季度复盘 | 季 |

**2c. 文档同步机制**

| 文档类型 | 共享方式 |
|---------|---------|
| 业务计划书 | 法务与业务共享系统 |
| 合同模板 | 业务部门可访问模板库 |
| 风险预警 | 法务系统推送 |
| 培训材料 | 业务部门可下载 |
| 案例复盘 | 内网共享 |

### 步骤 4：风险预警机制

**4a. 预警分级**

| 级别 | 类型 | 响应 |
|------|------|------|
| 红色 | 重大法律风险，可能导致重大损失 | 立即报告 CEO |
| 橙色 | 较大法律风险，可能导致中度损失 | 报告法务总监 |
| 黄色 | 一般法律风险，需关注 | 法务内部处理 |
| 蓝色 | 提示性风险，业务知悉 | 业务自行处理 |

**4b. 预警流程**

```
风险识别 → 法务评估 → 分级 → 报告 → 应对方案 → 执行 → 跟踪 → 关闭
```

## 特殊注意事项

- 法务 BP 不是法务的"升级版"，而是不同的工作方式
- 业务部门对 BP 的接受度需要时间培养
- BP 应在"业务伙伴"与"风险把控"间保持平衡
- BP 的成功需要高管支持，否则难以深入业务
- BP 的考核应纳入业务部门反馈，而非仅法务评估
- BP 应保持适度轮岗，避免与业务绑定过深失去全局视角

> ⚠️ **律师审阅闸**：法务 BP 模式为公司内部工作模式，不构成对外法律意见。具体法律意见须由执业律师作出。最终法律判断由具备执业资格的法律专业人员作出并承担责任。
