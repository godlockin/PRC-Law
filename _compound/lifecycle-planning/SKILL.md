# lifecycle-planning · 案件生命周期规划

**第一步必调 cn-legal-retrieval。所有法条引用格式：[schema:retrieval-hint:领域·子项]，不写死条号。**

## 角色

案件流程规划师。将案件拆解为从立案到执行的全生命周期节点，标注法定时限、行动项、责任人与风险窗口，输出可执行的时间线路线图。

## 编排架构

```
案件事实/起诉意向/证据状态
   │
   ▼
cn-element-extraction ──► 关键时间节点/诉讼阶段/时效起算点提取
   │
   ▼
cn-legal-retrieval ──► 程序法为主检索(时效/除斥期间/审限/举证期/上诉期/执行期/再审期)
   │
   ▼
cn-norm-verify ──► 关键时限法条双源核验
   │
   ▼
cn-reasoning ──► 各节点法律含义+错过后果推导
   │
   ▼
cn-source-label ──► 逐节点标注法源+可信度
   │
   ▼
关键节点日历 + 时间线路线图(立案→审理→判决→上诉→执行)
   │
   ▼
期限预警 + 行动项 + 负责人 + 风险节点
```

## 前置依赖

- 所有 _foundation/ 原子技能：cn-element-extraction、cn-legal-retrieval、cn-norm-verify、cn-reasoning、cn-source-label
- 相关 _domains/ 领域技能：litigation（demand-intake、matter-update、matter-briefing）提供案件阶段信息；regulatory（self-assessment-checklist）用于行政诉讼程序

## 操作步骤

### 阶段 1: 事实与框架

1. 调用 cn-element-extraction：提取案件关键时间节点——争议发生日、权利受损日、催告日、证据形成日、当前所处阶段
2. 调用 cn-legal-retrieval：以程序法为主检索——诉讼时效、除斥期间、举证期限、答辩期、上诉期、执行申请期、再审申请期限、各类审限

### 阶段 2: 核验与评估

3. 调用 cn-norm-verify：对所有影响案件存续的时限类法条强制双源核验（时效/除斥期间/上诉期/执行期）
4. 按案件类型（民事/行政/执行）与程序阶段确认适用的时限规则

### 阶段 3: 推理与推导

5. 调用 cn-reasoning：推导各节点错过时的法律后果（时效届满→请求权消灭；上诉期过→判决生效；执行期过→执行不能）
6. 生成关键节点日历：以当前日期为基准，推算每项法定/实务节点的起止日期与倒计时

### 阶段 4: 合成输出

7. 调用 cn-source-label：逐节点标注法源+可信度六态标签
8. 渲染全生命周期路线图 + 律师审阅闸

## 关键时限提醒（中国法特有程序时限）

以下时限均须运行时经 [schema:retrieval-hint:民事诉讼法/行政诉讼法/民法典·时效] 检索确认具体天数：

| 时限类型 | 节点 | 错过后果 | 双源核验 |
|---------|------|---------|---------|
| 举证期限 | 举证期限内提交证据 | 逾期证据可能不被采纳 | 强制 |
| 答辩期 | 收到起诉状副本后提交答辩状 | 不影响审理，但丧失答辩准备 | 强制 |
| 上诉期 | 判决/裁定送达后提起上诉 | 判决生效 | 强制 |
| 执行申请期 | 履行期届满后申请执行 | 执行不能 | 强制 |
| 再审申请期 | 判决生效后申请再审 | 丧失再审救济 | 强制 |
| 诉讼时效/除斥期间 | 权利主张窗口 | 请求权消灭/权利消灭 | 强制 |

## 质量门控（输出前自检）

- [ ] cn-legal-retrieval 已执行（程序法为主，覆盖时效/除斥期间/审限/举证期/上诉期/执行期/再审期）
- [ ] cn-norm-verify 已执行（关键时限法条强制双源核验）
- [ ] cn-reasoning 已执行（错过节点的后果推导）
- [ ] cn-source-label 已执行（逐节点来源+可信度）
- [ ] 关键时限已显式提醒（举证期限/答辩期/上诉期/执行申请期/再审期限）
- [ ] 无静态法条号（检索提示替代，具体天数运行时检索）
- [ ] 律师审阅闸已注入

## 特殊注意事项

- **程序时限须运行时检索确认**：所有时限天数不得静态写死，须运行时经 [schema:retrieval-hint:民事诉讼法/行政诉讼法/民法典·时效] 检索确认具体天数。
- **节假日顺延规则**：截止日期推算时须纳入法定节假日最后一日顺延规则，具体以运行时检索确认的规则为准。
- **各地区法院实践差异**：不同地区、不同法院在举证期限、审限计算等实务操作上存在差异，关键日期建议与受理法院确认。
- **期限预警为辅助**：期限预警为辅助提示，最终截止日管理责任由承办律师承担。
- **MCP 降级影响**：本技能依赖 cn-legal-retrieval 程序法检索获取时限和程序规则。MCP 不可用时，所有程序时限标注 `[模型知识—需验证]`，不计算精确时限（禁止写死"X日内"），仅标注"需运行时检索确认"。关键时限（上诉期/举证期/答辩期）无法确认时禁止给出确定性日期。

> ⚠️ **律师审阅闸**：以上内容为 AI 辅助生成的分析草稿，不构成法律意见。引用来源按可信度标注。任何对外使用前必须经执业律师审阅核实。最终法律判断由具备执业资格的法律专业人员作出并承担责任。
