# claim-chart · 要件分析表

**第一步必调 cn-legal-retrieval。所有法条引用格式：[schema:retrieval-hint:领域·子项]，不写死条号。**

## 角色

请求权要件分析师。将请求权的构成要件逐项拆解，映射到已有事实与证据，判断每项要件是否满足，并对不满足项给出补证建议。

## 编排架构

```
案件事实/侵权描述/民事争议
   │
   ▼
cn-element-extraction ──► 主体/行为/损害/因果关系/时间线/争议焦点
   │
   ▼
cn-legal-retrieval ──► 请求权基础检索(合同/侵权/物权/不当得利/无因管理)
   │
   ▼
cn-norm-verify ──► 要件规范+时效/除斥期间/举证责任 双源核验
   │
   ▼
cn-reasoning ──► 逐要件法律适用推理
   │
   ▼
cn-argument-chain ──► 逐要件构建论证链(要件→事实→证据→分析→判断)
   │
   ▼
cn-source-label ──► 逐要件标注来源+可信度
   │
   ▼
要件分析表(要件/原告主张/证据/被告抗辩/分析/判断/补证建议)
```

## 前置依赖

- 所有 _foundation/ 原子技能：cn-element-extraction、cn-legal-retrieval、cn-norm-verify、cn-reasoning、cn-argument-chain、cn-source-label
- 相关 _domains/ 领域技能：ip（clearance）处理专利/商标要件分析；litigation（matter-briefing）处理民事案由要件分析
- 跨法域对照（仅研究用途）：references/comparative/ 下的英美法抗辩资料

## 操作步骤

### 阶段 1: 事实与框架

1. 调用 cn-element-extraction：提取案件要素——主体、行为、损害后果、因果关系、时间线、争议焦点
2. 调用 cn-legal-retrieval：检索请求权基础——判断案由（合同/侵权/物权/不当得利等），定向检索该请求权之构成要件规范

### 阶段 2: 核验与评估

3. 调用 cn-norm-verify：对要件规范及程序性规范做双源核验（诉讼时效/除斥期间/举证责任分配）
4. 按要件逐项比对已有证据与事实，标注每项要件的证据支撑情况

### 阶段 3: 推理与推导

5. 调用 cn-reasoning：逐要件做法律适用推理——该要件之法律定义 → 案件事实是否落入 → 证据是否支撑
6. 调用 cn-argument-chain：逐要件构建论证链——要件定义(法源) → 原告主张 → 证据支撑 → 被告抗辩 → 分析 → 满足判断
7. 对不满足要件给出补证建议（缺失证据类型、调取途径、替代证据）

### 阶段 4: 合成输出

8. 调用 cn-source-label：逐要件标注来源+可信度六态标签
9. 渲染要件分析表 + 律师审阅闸

## 中国法抗辩 vs 英美法抗辩

- **中国大陆法抗辩体系**：逐要件分析时纳入中国法特有抗辩——诚实信用原则、公平原则、与有过失、减轻损失义务、重大误解/欺诈/胁迫/显失公平的效力抗辩，运行时经 [schema:retrieval-hint:民法典·总则编·诚实信用原则·公平原则·与有过失/减损义务/效力瑕疵抗辩] 检索确认
- **英美法抗辩**：仅用于跨法域案件对照研究，与主表隔离，置于 references/comparative/ 下；使用时加粗标注 **"仅用于跨法域研究"**，不得混入中国法要件判断

## 特殊注意事项

- **中国大陆法抗辩 vs 英美法抗辩隔离**：中国大陆法抗辩纳入逐要件分析；英美法抗辩仅用于跨法域案件对照研究，须隔离至 references/comparative/ 下并标注"仅用于跨法域研究"，不得混入中国法要件判断。
- **要件分析为策略辅助**：要件分析表为诉讼策略辅助工具，不替代律师对请求权是否成立、证据价值的独立判断。
- **补证建议为参考**：对不满足要件给出的补证建议仅为参考方向，证据收集与调取途径最终由承办律师决定。
- **MCP 降级影响**：本技能依赖 cn-legal-retrieval 请求权基础检索。MCP 不可用时，要件分析表中的法条引用全部标注 `[模型知识—需验证]`，不标注 `[已确认]`。

> ⚠️ **律师审阅闸**：以上内容为 AI 辅助生成的分析草稿，不构成法律意见。引用来源按可信度标注。任何对外使用前必须经执业律师审阅核实。最终法律判断由具备执业资格的法律专业人员作出并承担责任。
