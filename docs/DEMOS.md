# 律鉴演示案例与集成示例

> **v8.1 新增** (2026-08-04) — 完整的 IT/Demo 套件
> 目标：让律师/法务能在 5-10 分钟内体验律鉴完整能力
> 数据基础：基于元典真实 API 检索结果 + 最高法指导案例
> 严禁 mock 数据

## 设计原则

1. **真实性**：所有案例数据来自最高法指导案例（公开裁判文书），不是虚构
2. **跨能力**：每个案例至少跨越 5+ 个基础技能 + 1-2 个领域技能
3. **实用性**：选择律师/法务日常工作中**确实会遇到**的真实场景
4. **可重复**：每个 demo 可以完整跑一遍，结果可保存对照

## D1: 合同端到端审查（法务 · SaaS 服务协议）

### 场景背景

一家 SaaS 公司（甲方）拟与云服务商（乙方）签订三年期云服务协议。年合同金额 ¥500万。需法务在签约前完成全面审查。

### 涉及能力

- **cn-contract-full-review v2.0** (ORCHESTRATOR + 5-Agent)
- **cn-legal-retrieval** (类型定向检索)
- **cn-norm-verify** (双源核验)
- **cn-consequence-conflict** (违约责任后果)
- **cn-argument-chain** (Toulmin 论证)
- **cn-interpretation-audit** (6 阶解释)
- **cn-statute-watchdog** (法条状态监测)

### 输入材料

```
📄 SaaS 服务协议（简化版）

甲方：XX 科技有限公司
乙方：YY 云服务有限公司
合同期限：2026-09-01 至 2029-08-31
年费：¥500万/年
服务范围：云计算资源、CDN、对象存储、数据库托管

关键条款：
1. 服务等级协议（SLA）：99.9% 可用性
2. 数据安全：ISO 27001 认证、加密传输/存储
3. 责任限制：乙方总责任不超过 12 个月服务费
4. 终止条款：30 天通知期、违约金 50%
5. 数据迁移：合同终止后 90 天内提供数据迁移支持
6. 争议解决：仲裁，XX 仲裁委员会

待审查问题：
- SLA 99.9% 实际达不到的赔偿？
- 责任限制 12 个月服务费的合理性？
- 数据迁移 90 天是否足够？
- 争议解决条款的可执行性？
```

### 期望输出

```
📄 合同审查报告

7 章结构化报告：
1. 审查摘要（Executive Summary）
2. 5 维评分卡（合规 30% / 财务 25% / 防御 20% / 履行 15% / 商业 10%）
3. 6-Agent 详细发现（合规/量化/攻防/生命周期/商业/校对）
4. Agent 质量审计
5. 风险矩阵
6. 修订建议与谈判优先级
7. 来源标注与免责声明

时间：3-5 分钟
API 调用：8-12 次
```

### 跨能力验证

| 能力 | 在 D1 中的体现 |
|------|--------------|
| 法律检索 | SLA/责任限制/数据迁移条款定向检索 |

## D2: 时间锚点验证（律师 · 2007 年消费者案件）

### 场景背景

2007 年一位消费者购入家用汽车，发现经销商未告知维修记录。2026 年当事人委托律师代理。

**关键挑战**：本案发生在 2007 年，**应适用 1993 版消费者权益保护法**（第 49 条：退一赔一），而不是 2013 版（第 55 条：退一赔三）。

### 涉及能力

- **cn-legal-retrieval** (refer_date=2007-06-01 锁定历史版本)
- **cn-norm-verify** (法条版本效力核验)
- **cn-element-extraction** (事实+时间线)
- **cn-interpretation** (法条文义解释)
- **cn-civil-claim-analysis** (请求权基础)

### 输入

```
📄 案情简介（2007 年）

2007 年 2 月 28 日，张莉从北京合力华通汽车服务有限公司购买
上海通用雪佛兰景程轿车一辆，价格 ¥138,000。

2007 年 4 月，张莉发现该车在 2007 年 1 月 17 日（销售前）进行
过维修，但经销商未告知。

张莉起诉，主张：
- 撤销《汽车销售合同》
- 退还购车款 ¥138,000
- 赔偿三倍购车款 ¥414,000
```

### 关键差异验证

```
❌ 错误做法：用 2013 版消法第 55 条（退一赔三）→ 赔偿 ¥414,000
✅ 正确做法：用 1993 版消法第 49 条（退一赔一）→ 赔偿 ¥138,000
```

### 期望输出

```
📄 案例分析报告

1. 时间锚点确认：行为日 2007-02-28，适用 1993 版消法
2. 请求权基础：欺诈消费者
3. 适用法条：《消费者权益保护法》(1993 版) 第 49 条
4. 法条全文：经营者提供商品或者服务有欺诈行为的，应当按照
   消费者的要求增加赔偿其受到的损失，增加赔偿的金额为消费
   者购买商品的价款或者接受服务的费用的一倍。
5. 赔偿计算：¥138,000 × 1 = ¥138,000（双倍赔偿）
6. 时间锚点验证报告：✅ 行为时法定位正确
```

### 跨能力验证

| 能力 | 在 D2 中的体现 |
|------|--------------|
| 时间锚点 | refer_date=2007-06-01 锁定 1993 版 |
| 法条核验 | 双源比对 1993 版第 49 条 |
| 请求权基础 | 欺诈消费者 + 撤销合同 |
| 解释审计 | "欺诈行为"的文义+体系解释 |
| 结果预测 | 与最高法 17 号指导案例一致 |

## D3: 内部合规调查（法务总监 · 员工受贿）

### 场景背景

某销售部门员工被举报在过去一年收受供应商回扣约 ¥50 万。法务总监需要启动内部调查。

### 涉及能力

- **cn-internal-investigation** (内部调查全流程)
- **cn-evidence-evaluation** (证据三性+证明力)
- **cn-statute-watchdog** (监测相关法规变化)
- **cn-systematic-risk** (系统性风险矩阵)

### 输入

```
📋 举报材料

举报人：匿名（合规热线）
被举报人：销售经理 王某
涉嫌行为：收受 A 供应商、B 供应商回扣
可能涉及罪名：非国家工作人员受贿罪（刑法第 163 条）

初步证据：
- 供应商付款凭证（¥30 万、¥20 万）
- 王某与供应商的微信聊天截图
- 公司内部审计报告（异常关联）

需要：
1. 启动调查
2. 收集证据
3. 评估法律后果
4. 决定处理方式（解除+报案 vs 仅解除）
```

### 期望输出

```
📄 内部调查报告

1. 案件评估：高度严重
2. 证据清单：
   - 微信聊天截图：真实性 ✓ 合法性 ? 关联性 ✓
   - 付款凭证：真实性 ✓ 合法性 ✓ 关联性 ✓
   - 审计报告：真实性 ✓ 合法性 ✓ 关联性 ✓
3. 涉嫌罪名分析：
   - 非国家工作人员受贿罪（刑法第 163 条）
   - 公司内部处分依据：《员工手册》第 X 条
4. 处置建议：
   - 立即停职
   - 启动正式调查
   - 同步报案
   - 民事追偿（损失赔偿）
5. 风险评估：
   - 法律风险：高
   - 声誉风险：中
   - 合规风险：低（已发现）
```

## D5: 数据泄露响应（法务+IT · 紧急事件）

### 场景背景

公司用户数据库发生疑似泄露：50 万用户记录在暗网出现。法务与 IT 联合响应。

### 涉及能力

- **cn-data-breach-response** (数据泄露响应)
- **cn-PIA** (个人信息保护影响评估)
- **cn-systematic-risk** (系统性风险)
- **cn-statute-watchdog** (PIPL 法规变化)

### 输入

```
📋 事件报告

事件名称：用户数据库疑似泄露
事件级别：🔴 P0 紧急
影响范围：约 50 万用户
发现时间：YYYY-MM-DD HH:MM

初步调查：
- 攻击向量：第三方供应商漏洞
- 数据类型：姓名、电话、邮箱、地址
- 监管要求：个人信息保护法第 57 条（发生泄露立即告知）

需要在 24 小时内：
1. 评估法律风险
2. 启动监管报告
3. 准备用户通知
4. 控制舆情
```

```
   - 公安部网络安全等级保护
   - 工信部 APP 信息保护
```

## 使用方法

### 1. 选择 Demo

律师/法务根据当前需求选择 demo：

```
律师：常用 D1（合同审查）、D2（历史案件）、D4（诉讼策略）
法务：常用 D1（合同审查）、D3（内部调查）、D5（危机响应）
法学生：常用 D6（学习路径）
```

### 2. 准备输入材料

每个 demo 都有**真实输入模板**（基于最高法指导案例或公开案例），可以：
- 直接复用
- 修改当事人信息为本地化
- 提供给律鉴作为测试

### 3. 运行 Demo

```bash
# 律师跑合同审查
# 用户：在 Claude Code 中输入："请用律鉴审查这份 SaaS 合同"
# → 律鉴自动编排 D1 的完整链路

# 法务跑内部调查
# 用户："收到员工受贿举报，请按内部调查流程处理"
# → 律鉴自动编排 D3 的完整链路
```

### 4. 输出与对照

每个 demo 输出标准化的法律文档：
- 律师审阅闸
- 来源标注
- 风险评估
- 行动建议
