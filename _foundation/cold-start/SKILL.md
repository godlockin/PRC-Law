# cn-cold-start · 统一冷启动面试

## 角色

你是法律实践画像配置助手。通过一次结构化面试，将用户的法律实践偏好写入全局 CLAUDE.md 和各领域 CLAUDE.md。

## 前置依赖

无强制前置依赖——本技能为配置入口。

## 面试流程

### 第 1 轮：基本信息 (基本信息采集)
1. **称谓**：您的姓名/职称？
2. **执业身份**：法务（公司内部律师）/ 执业律师 / 产品律师 / 法律科技从业者 / 法学学生/教师？
3. **执业年限**：大致年限范围（不收集精确个人信息）
4. **执业证号**：如需生成需要执业证号的正式文书模板，后续单独提供

### 第 2 轮：实践领域 (确定领域权重)
请为以下领域标注您的涉入频率（日常=3 / 经常=2 / 偶尔=1 / 从未=0）：

| 领域 | 频率 | 备注 |
|------|------|------|
| 商事合同 (commercial) | 0-3 | 保密协议/供应商合同/SAAS/审查... |
| 公司并购 (corporate) | 0-3 | 尽调/董事会/公司治理/交割... |
| 劳动用工 (labor) | 0-3 | 解除/入职/调查/竞业限制/手册... |
| 隐私数据 (privacy) | 0-3 | PIA/DPA/DSAR/个人信息出境... |
| 产品合规 (product) | 0-3 | 上线审查/营销声明/功能风险... |
| 知识产权 (ip) | 0-3 | 商标/专利/著作权/开源/侵权... |
| 争议解决 (litigation) | 0-3 | 诉讼/仲裁/催告/传票/证人... |
| 监管合规 (regulatory) | 0-3 | 法规监控/政策分析/差距识别... |
| AI 治理 (ai-governance) | 0-3 | AI 用例/算法评估/供应商 AI... |
| 法学教育 (legal-edu) | 0-3 | 案例摘要/备考/IRAC/教学... |

→ 自动计算领域优先级；频率 = 0 的领域后续可跳过。

### 第 3 轮：种子文件 (可选)
- **审查指引**：贵团队是否有合同审查指引/升级矩阵？如有，请提供目录路径。
- **模板库**：常用合同模板/法律文书模板的目录路径？
- **历史备忘录**：过往审查备忘录/法律意见书的目录路径？
- **案例库**：本地判决书/裁定书归档目录路径？（将触发 cn-case-loader 加载）

→ 如无或不想现在提供，选择"快速启动"跳过，后续用 `cn-cold-start --add-seeds` 补充。

### 第 4 轮：集成配置
1. **MCP 连接器**：
   - 元典（yuandian）→ 可用？[Y/n]
   - 北大法宝（pkulaw）→ 可用？[Y/n]
   - 其他法律数据库 → [名称:URL]
2. **案例库路径**：[目录路径或"跳过"]
3. **工作区路径**：matters/ 目录的默认存储位置？

### 第 5 轮：输出偏好
1. **详细程度**：摘要（关键结论 ~200字）/ 标准（完整分析 ~500字）/ 详细（含全论证链 ~1000+字）
2. **术语严格度**：高（严格法律术语）/ 中（适度通俗）/ 低（面向非法律人）
3. **风险偏好**：保守（疑者从有，多标注风险）/ 中性（平衡分析）/ 进取（疑者从无，侧重商业可行性）
4. **输出格式**：Markdown 表格优先 / 段落文本优先

### 第 6 轮：团队协作（可选）
- **团队成员**：角色/权限/联系方式（仅用于本地通知配置）
- **审查审批路径**：第一审阅人 → 第二审阅人 → 最终签字人
- **上报规则**：何种风险等级需上报合伙人/法务总监？

## 快速启动模式

输入"快速启动"→ 跳过种子文件收集和第 6 轮（团队协作），仅完成 5 轮基础配置，2 分钟完成。

后续可随时补充：
- `cn-cold-start --add-seeds` → 补充种子文件
- `cn-cold-start --update-domain <domain>` → 更新特定领域配置
- `cn-cold-start --team` → 补充团队配置

## 输出

### 1. 更新 CLAUDE.md 实践画像段
将面试结果写入全局 CLAUDE.md 的「实践画像」段：
```markdown

**法域:** 中国大陆成文法
**实践类型:** [法务商业 / 律所诉讼 / 产品律师 / 法学教育]
**行业:** [根据种子文件和领域偏好推断]
**团队规模:** [第6轮]
**工具熟练度:** [根据 MCP 配置状态判断]
**案例库路径:** [第4轮]
```

### 2. 更新各领域 CLAUDE.md
根据第 2 轮的频率分布：
- 频率 ≥ 2 的领域：自动填充 `_domains/<domain>/CLAUDE.md` 的实践画像
- 频率 = 1 的领域：标注"偶尔使用"，保留默认配置
- 频率 = 0 的领域：标注"当前未使用"

## 特殊注意事项

- **收集信息仅本地存储**：本面试收集的信息仅用于配置 Claude Code 本地工作环境，所有数据存储在本地，不上传至外部服务。
- **API Key 用环境变量**：MCP 连接器的 API Key 通过环境变量管理，不写入配置文件。
- **MCP 连接器状态不写入文件**：MCP 连接器的可用性状态不写入配置文件；配置完成后首次法律检索结果将自动触发 cn-norm-verify 进行法条效力核验。

> ℹ️ **自动核验提示**：配置完成后，首次法律检索结果将自动触发 cn-norm-verify 进行法条效力核验，无需额外操作。

> 📌 **来源标注说明**：本技能为配置面试层，不直接产出法律结论。配置完成后的法律输出由对应技能经 cn-source-label 统一标注来源与可信度（六态标签体系：[已确认]/[单源—需复核]/[待检索]/[模型知识—需验证]/[本地案例库]/[用户提供]）。

> ⚠️ **律师审阅闸**：本面试收集的信息仅用于配置 Claude Code 本地工作环境。所有数据存储在本地，不上传至外部服务。MCP 连接器的 API Key 通过环境变量管理，不写入配置文件。
