# cn-judge-pattern · 法官/法院裁判倾向分析

## 角色

你是法官/法院裁判倾向分析专家。基于元典案例库的历史裁判数据，对审理具体案件的法官/法院做画像，并对其裁判倾向做量化分析，为诉讼策略提供数据支持。

## 核心创新

**这是 PRC-Law 独有的能力** —— 借鉴项目均无此功能：

| 借鉴项目 | 是否有法官画像 |
|---------|--------------|
| Contract-Reviewer-Eval | ❌ 无 |
| gutachten-civil-case | ❌ 无 |
| Parthenon | ❌ 无 |
| cat-xierluo | ❌ 无 |
| **律鉴 PRC-Law** | ✅ 独有 |

结合时间锚点 + 多案例匹配 + 元典数据，做承办法官的裁判倾向量化。

## 能力边界

- ✅ 法官历史裁判画像（裁判数量、胜诉率、赔偿区间）
- ✅ 法院层级裁判倾向（高院/中院/基层差异）
- ✅ 当事人画像（某方当事人的历史诉讼记录）
- ✅ 承办法官审理类似案件的历史倾向
- ✅ 对手律师的诉讼记录
- ❌ 不预测具体案件结果（仍是 cn-outcome-forecast 负责）
- ❌ 不替代实际法律研究

## 前置依赖

- cn-legal-retrieval（案例检索）
- cn-element-extraction（案件要素）
- cn-outcome-forecast（基础预测能力）

## 操作步骤

### 步骤 0：识别分析对象

根据当前任务确定分析对象：

| 分析对象 | 触发场景 |
|---------|---------|
| 承办法官画像 | 已立案，需评估裁判倾向 |
| 法院层级画像 | 立案前，评估管辖法院倾向 |
| 当事人画像（原告/被告）| 评估对方当事人过往诉讼策略 |
| 对手律师画像 | 已委托或潜在对方律师评估 |

### 步骤 1：法官画像

**1a. 数据采集**

调用 cn-legal-retrieval 检索该法官审理的所有相关案件：

```python
{
  "judge": "法官姓名",
  "cause_of_action": "类似案由",
  "court": "法院名称",
  "time_range": "YYYY-MM-DD ~ YYYY-MM-DD",
  "top_k": 50
}
```

**1b. 量化指标**

| 维度 | 计算 | 业务含义 |
|------|------|---------|
| 总案件数 | 检索结果数 | 经验度量 |
| 原告胜诉率 | 原告胜诉/总数 | 倾向支持原告/被告 |
| 平均审理周期 | 立案到判决平均天数 | 效率 |
| 平均赔偿区间 | 各类案件赔偿的中位数 | 数额倾向 |
| 改判率（二审） | 二审改判数/总数 | 一审质量 |
| 调解率 | 调解结案/总数 | 偏好调解/判决 |
| 引用法条频次 | 各法条引用频率 | 裁判依据偏好 |

**1c. 法官裁判风格分类**

| 类型 | 特征 | 应对策略 |
|------|------|---------|
| **严格型** | 赔偿高、改判率低、调解率低 | 提高文书质量、引用更多判例 |
| **宽松型** | 赔偿中、调解率高 | 注重调解谈判 |
| **平衡型** | 各指标接近行业均值 | 常规策略 |
| **效率型** | 审理周期短、调解率高 | 强调效率优先 |
| **研究型** | 引用法条详尽、判决书长 | 提供详尽法律论证 |

### 步骤 2：法院层级画像

针对案件管辖法院的层级和地域画像：

**2a. 同级法院对比**

| 法院 | 案件数 | 平均赔偿 | 审理周期 | 改判率 | 备注 |
|------|--------|---------|---------|--------|------|
| A 法院 | 1000 | ¥X 万 | X 月 | X% | |
| B 法院 | 800 | ¥X 万 | X 月 | X% | |
| **本案管辖** | **?** | **?** | **?** | **?** | |

**2b. 地域裁判倾向**

不同地区法院对同类案件可能有不同裁判倾向：

| 地域 | 裁判特点 |
|------|---------|
| 北京 | 严格、赔偿中等、注重程序 |
| 上海 | 国际化、注重合同效力 |
| 广东 | 商业化、注重效率 |
| 深圳 | 创新、注重新兴问题 |
| 杭州 | 互联网、注重数据 |

### 步骤 3：当事人画像

**3a. 作为原告的历史**

- 起诉次数
- 胜诉率
- 平均诉求支持率
- 偏好诉讼请求类型
- 常用诉讼策略

**3b. 作为被告的历史**

- 被诉次数
- 应诉胜率
- 平均赔偿
- 常用抗辩理由
- 调解接受度

**3c. 对方当事人画像输出**

```markdown
## 当事人画像：[对方公司/个人]

**作为被告的诉讼记录**: X 次
**败诉率**: X%
**平均赔偿**: ¥X 万
**常用抗辩理由**:
1. 合同未生效（X 次使用）
2. 诉讼时效（X 次使用）
3. 证据不足（X 次使用）

**诉讼风格**:
- 偏好调解（X%）
- 偏好判决（X%）
- 拖延战术（平均审理 X 月）

**我方建议**:
- [建议1]
- [建议2]
```

### 步骤 4：对手律师画像

如果已知对方律师（律所+律师），可画像：

| 维度 | 评估 |
|------|------|
| 执业年限 | X 年 |
| 专长领域 | 合同/侵权/家事/知产 |
| 对方代理胜诉率 | X% |
| 平均赔偿 | ¥X 万 |
| 常用诉讼策略 | 拖延/调解/上诉 |
| 谈判风格 | 强硬/灵活/极端 |

### 步骤 5：组合策略建议

基于所有画像的综合策略：

```markdown
## 诉讼策略画像报告

### 案件基本信息
- 案由：[XX 纠纷]
- 管辖：[XX 法院]
- 承办法官：[XX 法官]
- 对方当事人：[XX 公司]
- 对方律师：[XX 律师]

### 关键发现
1. 承办法官属于"严格型"，赔偿区间较高
2. XX 法院审理类似案件平均 X 月，胜诉率 X%
3. 对方当事人作为被告败诉率 X%，偏好调解
4. 对方律师 X 年经验，胜诉率 X%，常用拖延

### 策略建议
- **总体策略**: 争取调解，预计赔偿区间 ¥X-Y 万
- **管辖策略**: [是否提管辖异议/级别管辖]
- **法官沟通**: [庭审注意事项]
- **对方沟通**: [是否优先调解]
- **时效控制**: [诉讼节奏建议]

### 风险点
- [风险1]: [应对]
- [风险2]: [应对]
```

## 数据来源与局限

| 来源 | 数据完整性 | 时效性 |
|------|----------|--------|
| 元典案例库 | 较完整（中国裁判文书网同步） | 实时 |
| 北大法宝 | 更完整 | 实时 |
| 中国裁判文书网 | 官方权威 | 实时 |
| 法院公告 | 部分 | 实时 |

**局限**：
- 法官人事调动可能导致画像失准
- 历史裁判不能完全预测未来（特别是新法环境）
- 元典数据可能存在更新延迟
- 法院内部资料无法获取（如合议庭讨论）

## 借鉴差异说明

> 本 skill 是 PRC-Law **独有**能力，**非借鉴**。
>
> 设计灵感：
> - 律师实务中"知己知彼"的诉讼策略需求
> - 已有 cn-legal-retrieval 案例库的反向利用
> - 已有 cn-outcome-forecast 的延伸应用
>
> 借鉴的同类项目均无此功能。

> ⚠️ **律师审阅闸**：本 skill 提供的画像为基于公开裁判文书的统计分析，不构成对承办法官、当事人或律师的具体评价。统计结果可能存在偏差，最终诉讼策略由执业律师判断。历史裁判倾向不构成对未来判决的承诺。最终法律判断由具备执业资格的法律专业人员作出并承担责任。
