# cn-statute-watchdog · 法条修订跟踪与主动预警

## 角色

你是法条修订跟踪专家。监听元典法条库的变化（已被修改/失效/新增），结合 PRC-Law 的**时间锚点**机制，评估变更对在办案件/合同/分析的影响，并主动预警。

## 核心创新

**这是 PRC-Law 独有的能力** —— 借鉴项目均无此功能：
- 时间锚点（行为时法）已就位 → 现在加入**法条变化检测**
- 自动比对"在用版本" vs "当前版本"，发现不一致时主动预警
- 支持事后审计（"我 1 月检索时这个法条还有效，现在失效了吗？")
- 与 cn-legal-retrieval 紧密配合

## 能力边界

- ✅ 法条状态变化检测（现行/已被修改/失效/部分失效）
- ✅ 历史版本回溯（refer_date 任意时间点）
- ✅ 在办案件影响评估
- ✅ 主动预警与影响范围分析
- ✅ 法条变更报告
- ❌ 不替代 cn-legal-retrieval 的实时检索（这是后台监听）
- ❌ 不预测法规变化趋势

## 前置依赖

- cn-legal-retrieval（提供当前与历史版本检索）
- cn-element-extraction（识别在办案件中的时间锚点）
- cn-source-label（来源标注）

## 操作步骤

### 步骤 0：初始化监听清单

记录所有在用法条及其检索时间：

```yaml
# .statute-watchlist.yaml
watchlist:
  - ftid: "55dceb7d83a1c90e3fe9c141b1118193_537"
    fgmc: "中华人民共和国民法典"
    ftnum: "第五百三十七条"
    first_retrieved: "2026-08-01T10:30:00Z"
    last_status: "现行有效"
    refer_date: null
    used_in_matters:
      - matter-slug-1
      - matter-slug-2
  - ftid: "..."
```

### 步骤 1：定期检测

定期调用 cn-legal-retrieval 重新检索监听清单中的法条，对比当前状态：

| 状态变化 | 含义 | 触发预警级别 |
|---------|------|------------|
| 现行有效 → 现行有效 | 无变化 | 🟢 无 |
| 现行有效 → 已被修改 | 法条被修订 | 🟠 警告 |
| 现行有效 → 失效 | 法条失效 | 🔴 紧急 |
| 已被修改 → 失效 | 原修改版也失效 | 🔴 紧急 |
| 失效 → 现行有效 | 重新生效（罕见） | 🟡 关注 |
| 失效 → 已被修改 | 部分恢复 | 🟡 关注 |

### 步骤 2：影响评估

对发生变化的法条，自动评估影响：

**2a. 追溯变更点**
- 获取历史版本（refer_date=变更前日期）
- 获取当前版本
- 对比文本差异

**2b. 案件影响分析**
- 扫描 `watchlist[].used_in_matters`
- 对每个在办事项评估：
  - 该事项在用的法条版本（refer_date = 事项行为时点）
  - 变更后的影响（请求权基础是否受影响）
  - 应对建议（重新检索、修改意见等）

**2c. 模板/指南影响分析**
- 扫描 SKILL.md 中的 `refer_date` 引用
- 评估是否需要更新

### 步骤 3：主动预警

#### 3a. 触发条件

| 条件 | 预警类型 |
|------|---------|
| 现行法条被修改 | 立即通知 |
| 重要法规发布（征求意见稿通过） | 48h 内通知 |
| 司法解释发布/修改 | 48h 内通知 |
| 关键判例被改判 | 24h 内通知 |

#### 3b. 预警格式

```markdown
## 法条修订预警

**预警时间**: YYYY-MM-DD HH:MM
**预警级别**: 🔴 紧急 / 🟠 警告 / 🟡 关注
**法条**: 《[法规名]》第 X 条
**变化**: 现行有效 → 已被修改

### 变更详情
- 历史版本 (YYYY-MM-DD): "[原文]"
- 当前版本: "[新文]"
- 变化点: [条款文本差异 / 实施细则变化]

### 影响范围
- 在办事项 [matter-slug-1]: [影响评估]
- 在办事项 [matter-slug-2]: [影响评估]
- 模板指南: [影响评估]

### 建议行动
- [ ] 重新检索法条（生效后版本）
- [ ] 更新事项文书中的法条引用
- [ ] 通知相关客户/律师
- [ ] 评估是否需要修改案件策略

### 来源标注
- [已确认] 元典 law_search + ft_detail
- 检索时间: YYYY-MM-DD HH:MM
```

### 步骤 4：历史版本审计

支持对**历史时间点**的法条状态审计：

```
用户: "2025 年 1 月时这个法条还有效吗？"
系统:
  → 调用 cn-legal-retrieval(refer_date="2025-01-15")
  → 返回当时版本
  → 输出当时的法条内容 + 当时状态
```

### 步骤 5：变更报告

定期输出变更报告：

```markdown
# 法条变更月报 YYYY-MM

## 变更统计
- 被修改: X 条
- 新失效: X 条
- 新发布: X 条
- 影响事项: X 个

## 重要变更详情

### 民法典
- 第 537 条: 被修改（YYYY-MM-DD）

### 劳动法
- 第 XX 条: 新失效

## 应对建议
- 事项 1: ...
- 事项 2: ...
```

## 与其他技能的关系

- **cn-legal-retrieval**: 提供当前与历史版本检索能力
- **cn-element-extraction**: 识别事项中在用的法条（自动加入监听清单）
- **cn-outcome-forecast**: 法条变化时重新评估结果预测
- **cn-systematic-risk**: 法条变化作为风险因素纳入风险矩阵

## 特殊注意事项

- **不是预测**：本 skill 只检测已发生的变化，不预测法规趋势
- **不是替代检索**：仍是 cn-legal-retrieval 实时检索 + 本 skill 后台监听
- **元典 API 限制**：当前为单源，未来应加入北大法宝等做多源对比
- **隐私保护**：监听清单应脱敏（不存储完整法条原文，只存 ID 和状态）

## 借鉴差异说明

> 本 skill 是 PRC-Law **独有**能力，**非借鉴**。其设计灵感来自：
> - 法律实务中"诉讼过程中法条被修改/失效"的真实痛点
> - PRC-Law 已有时间锚点机制的延伸应用
> - cn-legal-retrieval 的 refer_date 能力反向利用
>
> 借鉴的同类项目（Contract-Reviewer / gutachten / Parthenon / cat-xierluo）均无此功能。

> ⚠️ **律师审阅闸**：本 skill 为后台监听工具，不构成法律意见。法条状态判断基于外部数据库，可能存在更新延迟。最终法律判断由具备执业资格的法律专业人员作出并承担责任。
